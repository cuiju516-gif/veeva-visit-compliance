# 学术拜访合规 · 交互 Demo

纯静态前端原型，用来**用点击理解 happy path、主要分支，以及两类使用者的权限边界**。不需要构建、不需要后端。

```
open demo/index.html          # 或直接双击
```

> 想找原始需求：见 [../docs/source-extracted.txt](../docs/source-extracted.txt)（题面 PDF 的文字提取稿）

---

## 30 秒上手

MR 的落地页是**我的拜访计划列表**（可排序），不是单条拜访：

1. 点任意一行的「打开」→ 进入该拜访的流程
2. 点坐标快捷点「医院正门 · 0 米」→ **签到**
3. 点右上角 **+10 分**（虚拟时钟，免去真的等 10 分钟）→ **签退**
4. 签退的瞬间时间与判定就锁定了，紧接着**自动弹出记录表单**（一次操作、两个时间点）：
   填谈话要点提交即可；点「稍后填」则停在「已签退 · 待填记录」

## 演示身份（左侧轨道切换）

身份切换是**演示装置**，放在最外层的左侧轨道里（标着「演示身份」），和产品内容区完全隔开。
一共 **3 个身份 / 2 类角色**：两名代表（张伟、李娜）+ 管理员。两名代表用来演示"数据隔离"——
李娜只看得到自己的几条，张伟的一条也看不见。
（原设计里的「区域主管」整层已移除：没有团队范围、没有代表筛选、没有异常复核。）
同一份数据，不同角色看到的东西不一样——点一下就能对照：

| 身份 | 落到哪个视图 | 能看到 / 能做什么 | 不能做什么 |
|---|---|---|---|
| **医药代表 张伟 / 李娜** | 我的拜访 | 只看**本人**的拜访；新建 / 修改 / **取消（需原因）** / **删除（免原因，窗口内）** / 签到 / 签退 / **作废（需原因）**；异常时看到差多少秒、多少米；我的月度统计 | 全量看板、改规则、**维护药品/医院/医生主数据** |
| **系统管理员 王敏** | 规则配置 | 阈值配置（版本化）、医院 / 医生 / 药品三张主数据的增删改与下线、**产品 × 月度看板（全量）**、待补记录 | 改拜访内容——业务数据对管理员只读 |

### MR 的列表能做什么

| 动作 | 入口 | 说明 |
|---|---|---|
| 排序 | 点表头「计划开始时间 / 状态 / 异常类型」 | 再点一次切换升降序；异常类型按「无 / 时长不足 / 地点偏离 / 两者」分组 |
| 筛选 | 状态 chips（全部/待签到/进行中/待补记录/已完成/已取消） | 计数实时更新 |
| 新建 | 右上「＋ 新建计划」 | 弹窗里**先选医院、再选医生**（医生列表按医院过滤）；三个字段都是**可搜索下拉**：输入即过滤，支持 ↑↓ 选择、回车确认、Esc 关闭；**计划时间不能早于当前时间**（日期 `min` + 提交时 400 兜底）；时间用**日期 + 24 小时制时分**（00–23 显式可选，不跟随浏览器 locale）；**1 小时内开始**的计划需要**二次确认** |
| 查看 | 点整行 | 进入 5 步流程；底部有「操作留痕」 |
| 修改 | 行内「⋯ → 修改计划」 | 仅「待签到」出现；必须填原因，写入操作留痕 |
| 取消 | 「⋯ → 取消（需原因）」 | 进「取消」统计（未去成） |
| 删除 | 「⋯ → 删除（纠错）」 | **免原因**；仅"创建后 1h 内 + 距开始 > 1h"才出现在菜单里，否则菜单底部提示"已进入执行窗口，只能取消" |
| 作废 | 「⋯ → 作废这次拜访」 | 仅「已签到」出现；需原因，作废时补判 R2 并留痕 |

**需要填原因或需要确认的动作，一律用对话框（居中弹窗），不在页面里展开表单**——避免撑开整页、打断浏览；
点背景、按 Esc、点 ✕ 都能关闭。

**每一行都有「⋯」，菜单里只列当前状态下真正能执行的动作**——不可用的动作不出现（不是禁用），菜单底部用一行小字解释为什么没有别的选项。
终态行的菜单里只剩「查看详情」+ 一句说明（"已完成：记录冻结"），affordance 保持一致：**每行都能点开 ⋯，只是里面能做的事不同**。
（整行也可以直接点，两个入口并存。）

八个值得点一遍的地方：

1. **代表改计划** → 列表里 #1028 点「修改」，把时间改到周四并填原因；保存后会生成一条留痕，打开详情最下方能看到"谁、何时、改了什么、为什么"。不填原因保存 → `400`；没有实际改动 → `400`。
2. **代表取消计划** → 待签到卡片点「取消计划」，填原因确认；记录变 `已取消`、不计入拜访次数但可查（取消不删记录）。签到之后再取消会返回 `409`。
3. **代表删除计划** → 列表 #1028 点「删除」，**不用填原因**，确认即删；行变灰并划线，点「显示已删除」可追溯。对已经进入执行窗口的计划，删除按钮是禁用的（悬停有说明），只能取消。
4. **代表作废** → 打开 #1030（进行中）→ 卡片里点「作废这次拜访」，选原因确认；状态变「已作废」。如果签到点距医院超过 500 米，卡片会显示**作废时补判**的结果——作废不会让异常消失。
5. **超时扫描** → 打开页面时系统已经跑过一轮：#1022（计划过期 171 小时）变「超时取消」，#1019（签到 243 小时未签退）变「超时作废」，日志里各有 1 条。
5b. **超时自动作废** → 打开页面时系统已把 #1019（签到 7 天没签退）扫成「超时作废」，日志里有 `系统超时作废` 一条；看板「作废率」把它算进分子。想看实时触发：打开一条已签到的拜访，把虚拟时钟 `+10 小时` 连续点 3 次即可越过 24 小时阈值。
6. **代表越权维护药品** → 右侧「分支探针」点"代表新增药品" → `403`。主数据入口对代表根本不存在。
7. **管理员看单条拜访** → 月度看板里点任意明细行，弹出只读详情（判定、距离、异常原因、谈话要点）。
   管理员没有「我的拜访」Tab：他要的是"看数 → 下钻"，不是逐条浏览。
8. **管理员改阈值 / 删主数据 / 看全量看板** → 规则配置的 v1→v2、药品表的「已删除」标记、切换「月度看板」Tab。

### 状态机（Plan 生命周期）

7 个状态、8 条迁移。完整图见 `assets/state-machine-v2.svg`，守卫与分支清单见 `../docs/角色模型.md`。

```
PLANNED ──签到──► CHECKED_IN ──签退──► CHECKED_OUT ──补记录──► REPORTED
   │                  │                    │
   ├─取消(需原因)─► CANCELLED              │   ← 三者都计入"完成"
   ├─删除(免原因)─► DELETED
   │  系统: 超时未签到 ──► CANCELLED (NO_CHECKIN)
   └─                 └─作废(需原因)──► VOIDED
                        系统: 超时未签退 ──► VOIDED (TIMEOUT)
```

**统计口径**：`完成 = CHECKED_OUT + REPORTED` · `取消 = CANCELLED` · `作废 = VOIDED` · `删除 = DELETED（不入账）`。
三个计数器互不重叠，页面加载时会先跑一次超时扫描（一条过期计划被自动取消、一条悬挂拜访被自动作废）。

### 三种"让拜访不作数"的区别

| 动作 | 谁能做 | 状态 | 进不进统计 | 证据 |
|---|---|---|---|---|
| 取消计划 | 代表（仅待签到，需原因）或系统超时 | `CANCELLED` | 进「取消」统计 | 无签到记录 |
| 删除计划 | 代表（仅窗口内，免原因） | `DELETED` | **不入账** | 无签到记录 |
| 作废拜访 | 代表（仅已签到，需原因）或系统超时 | `VOIDED` | 进「作废」统计 | **签到时间与坐标保留，且补判 R2** |

## 完整的 happy path（5 步）

| 步骤 | 操作 | 预期 |
|---|---|---|
| ① 计划 | 点「＋ 从头新建拜访」，选医生/产品/时间 → 创建计划 | 日志 `201`，状态 `已计划`，进度条走到第 2 步 |
| ② 签到 | 坐标用默认值（医院正门 0 米）→ 签到 | `200`，状态 `已签到`，开始实时计时 |
| ③ 沟通 | 点 **+10 分** 或卡片里的「⏩ 快进 5 分钟」 | `已停留` 实时增长；不足 5 分钟时会有黄色提示 |
| ④ 签退 | 点签退 | `200`，自动算出时长，判定「合规」 |
| ⑤ 记录 | 填谈话要点（必填）+ 反馈 + 是否派发资料 → 提交 | `200`，状态 `已完成`；看板该产品当月 +1 |

> 时间戳用**虚拟时钟**：签到/签退都取"当前虚拟时间"，所以可以先 `+10 分` 再签退，模拟真实停留 10 分钟。点「↺ 复位」回到真实时间。

## 主要分支（都有现成入口）

这些分支都可以用列表里现成的记录直接复现（不用点预设）：

| 分支 | 怎么触发 | 看到什么 |
|---|---|---|
| **B1 时长不足** | 预设 ②（3 分钟前签到）→ 点签退 | `异常` 红标；R1 `DURATION_TOO_SHORT`；时长 3 分 00 秒；流程仍可继续提交记录 |
| **B2 地点偏离** | 预设 ③（1.2 公里外）→ 点签退 | R2 `LOCATION_DEVIATION`；签到/签退点各 1199 米 |
| **B3 双重异常** | 预设 ④（2 分钟 + 2 公里）→ 点签退 | **3 项标记**：R1 一条 + R2 两条（签到点/签退点各一），全部返回、不覆盖 |
| **B4 未签到就签退** | 右侧「分支探针」→ 未签到就签退 | `409 非法状态流转`，数据不变 |
| **B5 重复签到** | 先签退？不行——用探针「重复签到」 | 在 `已签到` 状态下返回 `409`，签到时间不被覆盖 |
| **B6 未签退就提交报告** | 探针「未签退就提交报告」 | `409`，必须先拿到时长与判定 |
| **B7 坐标非法** | 探针「纬度填 200」/ 或自己在输入框填 200 再签到 | `400 坐标越界`，不落库 |
| **B8 经纬度写反** | 探针「经纬度写反」（纬度 121.47、经度 31.23） | `400 疑似经纬度写反` |
| **B9 计划时间不在下周** | 新建拜访时把时间选到 7 天以后或过去 | `201` + 黄色软提示，**不阻断**（原文未强制） |
| **B10 只计划未发生** | 看板里找 #1028 | 不计入任何月份——"计划 ≠ 拜访发生" |

### 三类结果要分清

- **200 + flag**：业务成功，但被判定异常。异常拜访照样落库、照样进看板，只是标红。
- **400**：入参错误（缺坐标、越界、必填为空）。
- **409**：状态冲突（顺序错了）。这类请求一条数据都不改。

## 界面结构

```
我的拜访   计划列表（可排序、可筛选）+ 行内 ⋯ 操作；点整行进详情
月度看板   产品×月份统计 + 明细（点行看只读详情）+ 待补记录；表格下方一行「统计口径」
规则配置   规则阈值 + 版本历史 + 医院/医生/药品三张主数据表（仅管理员）
          右：合规判定（R1/R2 逐条打勾）、分支探针、事件日志（模拟接口返回）
月度看板   按产品 × 月份的拜访次数 + 异常率 + 明细
规则与分支 判定口径、状态机表、happy path 清单、B1–B10 分支地图
```

## 已知边界（这是原型，不是成品）

- 数据在内存，**刷新即重置**为种子数据（10 条历史拜访 + 1 条仅计划的）。
- 没有真实认证：身份是顶部的切换按钮（模拟 actor）。但数据范围与权限判断是按角色走的，越权调用返回 `403`。
- 规则阈值可配置且带版本；判定结果存阈值快照，历史不重算。
- 主数据是**内存表**（医院/医生/药品），刷新即恢复种子；真实实现要落库。
- 主数据删除是**逻辑删除**：`deleted_at` 标记 + 默认不展示，库里从不物理删除；历史记录靠拜访上的快照照常可读。
- 复核只存结论与备注，没有审批流；生产环境通常要"双人复核 + 通知代表"。
- 作废是**自助**的：代表填原因即可，无需审批；作废时补判 R2 并写进作废记录。
- 超时扫描在每次渲染/每秒 tick 时跑，真实系统应交给定时任务或 DB 侧 job，并且幂等。
- **已完成的拜访在本原型中一律冻结**（不可改、不可删），只保留了"更正申请"的文案出口。
  这条策略集中在 `app.js` 的 `editable = v.status === 'PLANNED'` 一处，改成别的口径只需动这里。
- 校验函数与界面解耦，便于将来搬到服务端；真实系统里时间戳必须由服务端盖章，不能信前端。
- 坐标取点用等距近似（`pointAt`），所以"2 公里"实际算出来约 1998 米；判定用的是真 Haversine。
