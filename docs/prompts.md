## 一、Schema 设计

### 1. 角色 → 数据归属字段

**我**：
> 系统的直接使用者应该至少包括3个：MR，M2（区域主管）和系统管理员 admin。MR负责创建计划、签到、签退、
> 填写记录；M2可以看团队的数据；admin负责规则和基础数据。

**AI 的第一版**：给了三张表（mr / hcp / product / visit），visit 上只有 `mr_id`，主管视角靠"查全部再筛"。

**我追问**：
> "按产品维度统计月度拜访次数"这句话，对这三个人是同一个查询吗？

**结论**：不是。同一个看板，MR 是 `WHERE mr_id = me`，主管是 `WHERE team_id = my_team`，
管理员是"全部且按规则版本分组"。**角色模型的第一产出不是权限表，而是数据模型上的归属字段**——
所以 `mr.team_id` 曾经真的加进了 schema。

> 后来主管整层被砍掉，`team_id` 变成死字段。教训：加一列只要一行 DDL，删它要改 ERD、契约、ADR 三处。
> 契约里因此留下了那句"若要恢复团队视角，是重新引入角色 + 组织模型，不是加一列"。

### 2. 判定要存证据，不能只存布尔

**我**：
> 阈值要可配（5 分钟 / 500 米），管理员可以改。

**AI 的第一版**：`visit.abnormal boolean`——改阈值后重算即可。

**我否定**：
> 那昨天判合规的记录，今天改完阈值就变异常了？审计问"当时为什么这么判"，我拿什么答？

**结论**：判定必须是**带版本的证据**：`{flags, durationSec, distanceIn, distanceOut,
thresholds, ruleVersion, evaluatedAt, source}`。改阈值只影响之后的判定，历史快照永不改写。
这就是 `visit.evaluation` 那一列。

**顺带定下的两条**：
- `thresholds` 在快照里**再存一份**，不能只存 `ruleVersion`——版本行本身也可能被改错；
- 作废没有签退，所以 `durationSec` 必须是 `null` 而不是 `0`：**"不知道"和"零"是两件事**。

### 3. `visit_flag` 不能有唯一约束

**我**：
> 地点规则是签到、签退各判一次。

**AI 的第一版**：`UNIQUE (visit_id, code)`，"一条规则一行"。

**冲突**：两次都偏离 → 两行同码 → 唯一约束让**异常最严重的那条**插不进去，整笔签退回滚成 500。

**结论**：不加唯一约束，行数表示命中次数；改用一个 `point` 列区分签到点/签退点，
并用 `chk_visit_flag_point_by_code` 保证"R1 无点别、R2 必有点别"——这条 CHECK 防的是另一类错误，
不承担去重职责。

## 二、复杂校验算法

### 4. 边界到底取哪一边

**我**：
> 停留时长不足 5 分钟算异常，签到/签退距离医院 500 米以上算异常。边界值要不要算合规？

**结论**：两个都取严格不等——`duration < 300` 异常（300 秒合规）、`distance > 500` 异常（500 米合规）。
"不足"和"以上"在中文里就是严格的。这条看起来小，但它决定了评审时那两个数字站不站得住。

### 5. 距离比较要不要容差

**AI 的第一版**：`distance > 500`。

**问题**：浮点噪声会让"正好 500 米"在个别坐标上判成异常。

**结论**：加 `1e-6` 米的比较容差，**并把它写成有名字的函数**：

```go
func exceedsLimit(distance, limit float64) bool {
    return distance > limit+distanceEpsilonMeters
}
```

理由：容差是"吸收浮点噪声"，不是"放宽 500 米"——500.4 米仍然异常。如果只通过 haversine 测，
`>` 和 `>=` 的区别会被噪声淹没，改坏了也没人发现。所以这个函数单独测。

### 6. 作废要不要重跑规则

**我**：
> 代表可以自己作废已签到的拜访，不需要审批。

**AI 的第一版**：作废就是把状态改掉。

**我追问**：
> 那异常拜访作废之后，异常就"没发生过"了？

**结论**：作废必须**补判**——用已有的签到时间与坐标重跑 R2，把 flags 写进作废记录。
作废能让这条拜访离开"完成"计数，但不能带走它的异常。系统超时作废走**同一条代码路径**，
只是 `cause` 不同。

## 三、实现与交付

### 7. 超时由谁推动

**我**：
> 不装定时任务，读的时候顺手处理行不行？

**结论**：可以，而且更安全——正确性不再依赖"调度器活着"。代价是读会写，所以两条边都写成幂等：
计划边是一条带条件的 `UPDATE`，签到边用 `FOR UPDATE SKIP LOCKED` 取候选。
失败时**宁可 500 也不返回自己知道过期的数据**。

### 8. 授权按动作判

**我**：
> MR1 不应该可以为 MR2 创建计划。

这一句引出的审计见报告 §3.2：**六个写接口都没判归属**，一个代表能把别人的拜访签退掉。

### 9. 交付前从干净克隆验

**我**：
> 检查需要提交的内容是否已经齐备。

结论：不能在工作区里自测。干净克隆一跑，测试里写死的日期当场炸（报告 §3.3）。
