## §2 数据模型

### 2.1 ERD（文本）

```
hospital ──< hcp ──< visit >── mr
     │                 │
     │                 ├──< visit_flag        （0..N；R2 逐点判定 → 同码可多行）
     │                 └──< visit_material    （派发的资料）
     │
     └─ base_lat/base_lng 是 R2 的唯一参照点（降级/删除后历史仍读 visit 上的快照）

product ──< visit           rule_version ──< visit.rule_version / visit_flag.rule_version
```

新增列与新表用 **★** 标记；其余是 v1 已有结构（`internal/store/migrations/0001_init.sql`）。

| 表 | 关键列 | 说明 |
|---|---|---|
| `mr` | id, name, region | 无团队字段：主管这一层已裁掉（2026-10-29 精简） |
| **★`hospital`** | id, name, base_lat, base_lng, status, deleted_at | **裁决 6-2 = B**：医院独立成表；v1 把坐标冗余在 `hcp` 上 |
| `hcp` | id, name, department, **★hospital_id**, status, deleted_at | 医生→医院改为外键；`hospital_name/base_lat/base_lng` **从本表移除** |
| `product` | id, code, name, **★status**, **★deleted_at** | — |
| `visit` | 见 §2.4 矩阵；**★** 7 个状态、终态原因、`evaluation`、6 列快照 | 核心表；快照仍是判定与展示的唯一来源 |

| **★`rule_version`** | version(PK), min_duration_sec, max_distance_m, created_at, created_by, note | 阈值版本化（需求说明 §6） |

### 2.2 现状 → 目标（改造清单的六处 + 裁决追加的第七处）

| # | 改动 | v1 现状 | 目标 |
|---|---|---|---|
| 1 | 状态 4 → 7 | `chk_visit_state_evidence` 只认 4 个状态 | 加 `CANCELLED`/`VOIDED`/`DELETED`，约束按 §2.4 重写 |
| 2 | 终态原因与时间 | 无 | `cancel_reason/cancelled_at/void_reason/void_cause/voided_at/deleted_at/reported_at` |

### 2.3 全量 DDL：`0003_contract_v2.sql`

可直接在已应用 0001+0002 的库上执行。**执行前先跑 §2.6 的两条预检**。

```sql
BEGIN;

-- ---------------------------------------------------------------------------
-- 1. 规则版本表（先建，visit.rule_version 要引用它）
-- ---------------------------------------------------------------------------
CREATE TABLE rule_version (
    version          text             PRIMARY KEY,
    min_duration_sec integer          NOT NULL CHECK (min_duration_sec > 0),
    max_distance_m   double precision NOT NULL CHECK (max_distance_m > 0),
    created_at       timestamptz      NOT NULL DEFAULT now(),
    created_by       text             NOT NULL DEFAULT 'system',
    note             text             NOT NULL DEFAULT ''
);

INSERT INTO rule_version (version, min_duration_sec, max_distance_m, created_by, note)
VALUES ('v1', 300, 500, 'system', '题面默认阈值：不足 5 分钟 / 超过 500 米');

-- ---------------------------------------------------------------------------
-- 2. visit：去掉旧状态约束，加终态字段、判定快照、展示快照
-- ---------------------------------------------------------------------------
-- 0001 里的 status 是内联 CHECK，PG 自动命名为 visit_status_check；
-- 只删 chk_visit_state_evidence 会留下它继续拒绝新状态（实测踩过，见 ADR 0002）。
ALTER TABLE visit
    DROP CONSTRAINT IF EXISTS chk_visit_state_evidence,
    DROP CONSTRAINT IF EXISTS visit_status_check;

ALTER TABLE visit
    ADD COLUMN cancel_reason  text,
    ADD COLUMN cancelled_at   timestamptz,
    ADD COLUMN void_reason    text,
    ADD COLUMN void_cause     text,
    ADD COLUMN voided_at      timestamptz,
    ADD COLUMN deleted_at     timestamptz,
    ADD COLUMN reported_at    timestamptz,
    ADD COLUMN evaluation     jsonb,
    ADD COLUMN rule_version   text REFERENCES rule_version (version),
    ADD COLUMN hcp_name       text,
    ADD COLUMN department     text,
    ADD COLUMN hospital_name  text,
    ADD COLUMN base_lat       double precision,
    ADD COLUMN base_lng       double precision,
    ADD COLUMN product_name   text;

ALTER TABLE visit
    ADD CONSTRAINT chk_visit_void_cause CHECK (void_cause IS NULL OR void_cause IN ('MANUAL', 'TIMEOUT'));

-- ---------------------------------------------------------------------------
-- 3. 回填：展示快照（历史记录从此不再依赖主数据现状）
-- ---------------------------------------------------------------------------
UPDATE visit v
   SET hcp_name      = h.name,
       department    = h.department,
       hospital_name = h.hospital_name,
       base_lat      = h.base_lat,
       base_lng      = h.base_lng,
       product_name  = p.name
  FROM hcp h, product p
 WHERE h.id = v.hcp_id
   AND p.id = v.product_id;

ALTER TABLE visit
    ALTER COLUMN hcp_name      SET NOT NULL,
    ALTER COLUMN department    SET NOT NULL,
    ALTER COLUMN hospital_name SET NOT NULL,
    ALTER COLUMN base_lat      SET NOT NULL,
    ALTER COLUMN base_lng      SET NOT NULL,
    ALTER COLUMN product_name  SET NOT NULL;

-- ---------------------------------------------------------------------------
-- 4. 回填：report 时间（旧数据没有该列；取最近更新时间作为上界）
-- ---------------------------------------------------------------------------
UPDATE visit SET reported_at = updated_at WHERE status = 'REPORTED' AND reported_at IS NULL;

-- ---------------------------------------------------------------------------
-- 5. visit_flag：加 point / rule_version（仍不加唯一约束）
-- ---------------------------------------------------------------------------
ALTER TABLE visit_flag
    ADD COLUMN point        text CHECK (point IS NULL OR point IN ('checkin', 'checkout')),
    ADD COLUMN rule_version text REFERENCES rule_version (version);

-- 历史行没有 point：v1 的 detail 前缀是固定的（"check-in …" / "check-out …"），按前缀回填。
-- 认不出来的行会让下一条约束失败——这是有意的：宁可迁移失败，也不要留一条点别为空的 R2 证据。
UPDATE visit_flag
   SET point = CASE
           WHEN detail LIKE 'check-in%'  THEN 'checkin'
           WHEN detail LIKE 'check-out%' THEN 'checkout'
       END
 WHERE code = 'LOCATION_DEVIATION' AND point IS NULL;

ALTER TABLE visit_flag ADD CONSTRAINT chk_visit_flag_point_by_code CHECK (
    (code = 'DURATION_TOO_SHORT' AND point IS NULL)
    OR (code = 'LOCATION_DEVIATION' AND point IS NOT NULL)
);

COMMENT ON COLUMN visit_flag.point IS
    'R2 逐点判定的点别。不要给 (visit_id, code) 加唯一约束：两点都偏离时必然同码两行，'
    '加约束会把一次真实的合规异常变成服务端错误（实现范围与改造清单 §4）。';

-- ---------------------------------------------------------------------------
-- 6. 回填：判定快照（距离无法在 SQL 里算，置 null，由 re-evaluate 任务补齐）
-- ---------------------------------------------------------------------------
UPDATE visit v
   SET rule_version = 'v1',
       evaluation = jsonb_build_object(
           'durationSec',  v.duration_seconds,
           'distanceInM',  NULL,
           'distanceOutM', NULL,
           'flags', COALESCE((
               SELECT jsonb_agg(jsonb_build_object(
                          'code',   f.code,
                          'point',  f.point,
                          'detail', f.detail) ORDER BY f.code, f.point)
                 FROM visit_flag f
                WHERE f.visit_id = v.id), '[]'::jsonb),
           'abnormal', EXISTS (SELECT 1 FROM visit_flag f WHERE f.visit_id = v.id),
           'thresholds', jsonb_build_object('minDurationSec', 300, 'maxDistanceM', 500),
           'ruleVersion', 'v1',
           'evaluatedAt', to_jsonb(COALESCE(v.checkout_at, v.updated_at)),
           'source', 'backfill_migration')
 WHERE v.checkin_at IS NOT NULL
   AND v.checkout_at IS NOT NULL;

UPDATE visit_flag SET rule_version = 'v1' WHERE rule_version IS NULL;

-- ---------------------------------------------------------------------------
-- 7. 新状态约束：状态 × 证据（见 §2.4）
-- ---------------------------------------------------------------------------
ALTER TABLE visit ADD CONSTRAINT chk_visit_state_evidence CHECK (
    CASE status
        WHEN 'PLANNED' THEN
            checkin_at IS NULL AND checkout_at IS NULL AND duration_seconds IS NULL
            AND cancel_reason IS NULL AND void_reason IS NULL AND deleted_at IS NULL
        WHEN 'CHECKED_IN' THEN
            checkin_at IS NOT NULL AND checkout_at IS NULL AND duration_seconds IS NULL
            AND cancel_reason IS NULL AND void_reason IS NULL AND deleted_at IS NULL
        WHEN 'CHECKED_OUT' THEN
            checkin_at IS NOT NULL AND checkout_at IS NOT NULL AND duration_seconds IS NOT NULL
            AND cancel_reason IS NULL AND void_reason IS NULL AND deleted_at IS NULL
        WHEN 'REPORTED' THEN
            checkin_at IS NOT NULL AND checkout_at IS NOT NULL AND duration_seconds IS NOT NULL
            AND cancel_reason IS NULL AND void_reason IS NULL AND deleted_at IS NULL
            AND reported_at IS NOT NULL
            AND talking_points IS NOT NULL AND btrim(talking_points) <> ''
        WHEN 'CANCELLED' THEN
            checkin_at IS NULL AND checkout_at IS NULL AND duration_seconds IS NULL
            AND cancel_reason IS NOT NULL AND cancelled_at IS NOT NULL
            AND void_reason IS NULL AND deleted_at IS NULL
        WHEN 'VOIDED' THEN
            checkin_at IS NOT NULL AND checkout_at IS NULL AND duration_seconds IS NULL
            AND void_reason IS NOT NULL AND void_cause IS NOT NULL AND voided_at IS NOT NULL
            AND cancel_reason IS NULL AND deleted_at IS NULL
        WHEN 'DELETED' THEN
            checkin_at IS NULL AND checkout_at IS NULL AND duration_seconds IS NULL
            AND deleted_at IS NOT NULL
            AND cancel_reason IS NULL AND void_reason IS NULL
        ELSE false
    END
);

COMMENT ON COLUMN visit.status IS
    'text + CHECK，不用 PG enum：枚举值扩展要 ALTER TYPE 且不能在事务里回滚语义，'
    '而这里的状态集合还会随业务演进（需求说明 §3.1 已扩过一次，4 → 7）。';

-- ---------------------------------------------------------------------------
-- 8. 主数据：逻辑删除（医院独立成表）
-- ---------------------------------------------------------------------------
-- 8.1 医院独立成表（裁决 6-2 = B）。必须在第 3 步之后：那一步读的是 hcp 上的旧列。
CREATE TABLE hospital (
    id         uuid             PRIMARY KEY DEFAULT gen_random_uuid(),
    name       text             NOT NULL,
    base_lat   double precision NOT NULL CHECK (base_lat BETWEEN -90 AND 90),
    base_lng   double precision NOT NULL CHECK (base_lng BETWEEN -180 AND 180),
    status     text             NOT NULL DEFAULT 'ACTIVE'
        CHECK (status IN ('ACTIVE', 'INACTIVE')),
    deleted_at timestamptz,
    created_at timestamptz      NOT NULL DEFAULT now()
);

-- 同一医院可能有多位医生，按 (名称, 坐标) 去重后各生成一行。
INSERT INTO hospital (name, base_lat, base_lng)
SELECT DISTINCT ON (h.hospital_name, h.base_lat, h.base_lng)
       h.hospital_name, h.base_lat, h.base_lng
  FROM hcp h
 ORDER BY h.hospital_name, h.base_lat, h.base_lng;

CREATE UNIQUE INDEX uq_hospital_identity
    ON hospital (name, base_lat, base_lng) WHERE deleted_at IS NULL;

ALTER TABLE hcp ADD COLUMN hospital_id uuid REFERENCES hospital (id);

UPDATE hcp h
   SET hospital_id = s.id
  FROM hospital s
 WHERE s.name     = h.hospital_name
   AND s.base_lat = h.base_lat
   AND s.base_lng = h.base_lng;

ALTER TABLE hcp ALTER COLUMN hospital_id SET NOT NULL;

-- 坐标与院名从此只有一处定义；历史拜访仍读 visit 上的快照。
DROP INDEX idx_hcp_site;
ALTER TABLE hcp
    DROP COLUMN hospital_name,
    DROP COLUMN base_lat,
    DROP COLUMN base_lng;

CREATE INDEX idx_hcp_hospital ON hcp (hospital_id, department);

-- 8.2 主数据逻辑删除
ALTER TABLE hcp
    ADD COLUMN status     text        NOT NULL DEFAULT 'ACTIVE'
        CHECK (status IN ('ACTIVE', 'INACTIVE')),
    ADD COLUMN deleted_at timestamptz;

ALTER TABLE product
    ADD COLUMN status     text        NOT NULL DEFAULT 'ACTIVE'
        CHECK (status IN ('ACTIVE', 'INACTIVE')),
    ADD COLUMN deleted_at timestamptz;

-- 8.3（无）团队归属：主管角色已裁掉，`mr` 不加 `team_id`。

COMMENT ON COLUMN hcp.deleted_at IS '逻辑删除：永不做物理删除。历史拜访读 visit 上的快照，不读本表。';
COMMENT ON COLUMN hospital.base_lat IS 'R2 的唯一参照点。改坐标不回算历史拜访（判定快照已落库）。';

-- ---------------------------------------------------------------------------
-- 9. 索引
-- ---------------------------------------------------------------------------
CREATE INDEX idx_visit_mr_status        ON visit (mr_id, status, planned_at DESC);
CREATE INDEX idx_visit_rule_version     ON visit (rule_version);
CREATE INDEX idx_visit_stale_checkin    ON visit (checkin_at) WHERE status = 'CHECKED_IN';
CREATE INDEX idx_hcp_available          ON hcp (status) WHERE deleted_at IS NULL;
CREATE INDEX idx_product_available      ON product (status) WHERE deleted_at IS NULL;
CREATE INDEX idx_hospital_available     ON hospital (status) WHERE deleted_at IS NULL;

COMMIT;
```

**已验证（不是"应该能跑"）**：本文 DDL 在 **PostgreSQL 16.15** 上、对 0001+0002 的种子库副本完整执行通过，
随后用 8 条探针确认约束真的在挡：

| 探针 | 结果 |
|---|---|
| `PLANNED → CANCELLED`（带原因+时间）/ `CHECKED_IN → VOIDED`（带 cause）/ `PLANNED → DELETED` | `UPDATE 1` ✅ |
| `VOIDED` 同时带签退 / `CANCELLED` 无原因 / `REPORTED` 谈话要点为空 / 非法 `void_cause` | 被拒 ✅ |
| 同一拜访插入两条 `LOCATION_DEVIATION` | 两次 `INSERT 0 1` ✅（无唯一约束） |

迁移不能只靠读：0001 的 `status` 是内联 CHECK，PG 自动命名 `visit_status_check`，
只删 `chk_visit_state_evidence` 会留下它继续拒绝新状态——这条是跑出来的，不是看出来的（记在 ADR 0002）。

**为什么没有 `DROP INDEX uq_visit_mr_active`**：一个代表同时只能在一个拜访上"已签到"，这条唯一索引是状态机的数据层兜底，7 状态后依然成立。`[derived]`

### 2.4 状态 × 证据矩阵

| 状态 | `checkin_at` | `checkout_at` | `duration_seconds` | 终态原因 | 时间戳列 |
|---|---|---|---|---|---|
| `PLANNED` | NULL | NULL | NULL | 无 | — |
| `CHECKED_IN` | NOT NULL | NULL | NULL | 无 | — |
| `CHECKED_OUT` | NOT NULL | NOT NULL | NOT NULL | 无 | — |
| `REPORTED` | NOT NULL | NOT NULL | NOT NULL | 无 | `reported_at` NOT NULL，`talking_points` 非空 |
| `CANCELLED` | NULL | NULL | NULL | `cancel_reason` NOT NULL | `cancelled_at` NOT NULL |
| `VOIDED` | **NOT NULL** | **NULL** | NULL | `void_reason` + `void_cause` NOT NULL | `voided_at` NOT NULL |
| `DELETED` | NULL | NULL | NULL | 无（免原因） | `deleted_at` NOT NULL |

对应 CHECK 就是 §2.3 第 7 段。三条硬约束写在表上而不是只写在代码里：数据库是唯一一个所有写入路径都必须经过的地方。`[derived]`

### 2.5 必须明确的三件事

1. **`VOIDED` 有签到、无签退**（`duration_seconds` 为 NULL）；`CANCELLED` / `DELETED` 两者皆无。
   依据：作废只从 `CHECKED_IN` 出（需求说明 §3.2 迁移 6），而时长只在签退时产生（§3.3 不变量 1）。
   由此 `chk_visit_duration_matches`（v1 已有）无需修改——它已经规定"缺任一时间戳则 duration 必须为 NULL"。

2. **`visit_flag` 不能有 `UNIQUE (visit_id, code)`**。地点规则逐点判定，两点都偏离时必然同码两行；
   加唯一约束会把"异常最严重"的路径变成 500（`实现范围与改造清单.md` §4）。约束替代方案：
   `chk_visit_flag_point_by_code`——R1 无 point、R2 必须有 point。这条 CHECK 防的是另一类错误（R2 忘了带点别），
   不承担去重职责。

3. **状态列是 `text + CHECK`，不是 PG enum**。`[derived]` 理由：v1 → v2 已经从 4 个状态扩到 7 个，
   而 PG 的 `ALTER TYPE ... ADD VALUE` 不能在事务块里执行、也不能回滚，迁移脚本会因此被拆成两段。
   代价是状态值没有类型级校验，靠 CHECK 兜底。

### 2.6 执行前预检（三条，任一非零就先处理）

```sql
-- ① REPORTED 但谈话要点为空：迁移后 chk_visit_state_evidence 会直接失败。
--    这是"该有的记录没有"，必须人工确认后再补，不能靠约束放宽掩盖。
SELECT id, planned_at FROM visit
 WHERE status = 'REPORTED' AND (talking_points IS NULL OR btrim(talking_points) = '');

-- ② 主数据被删过的行（v1 没有 deleted_at，所以这条只用于确认没有脏数据）
SELECT count(*) FROM visit v
  LEFT JOIN hcp h ON h.id = v.hcp_id
  LEFT JOIN product p ON p.id = v.product_id
 WHERE h.id IS NULL OR p.id IS NULL;

-- ③ 医院独立成表（裁决 6-2 = B）的前置：hcp 上的旧列不能为空，
--    否则 §8.1 的回填 JOIN 匹配不上，hcp.hospital_id SET NOT NULL 会直接失败。
SELECT count(*) FROM hcp
 WHERE hospital_name IS NULL OR base_lat IS NULL OR base_lng IS NULL;
```

## §3 `evaluation` 契约

### 3.1 形状

存于 `visit.evaluation`（jsonb）。**一条拜访只有一个当前判定**，重算会覆盖并写入新的 `evaluatedAt`
（需求说明 §3.3 不变量 2：改阈值不回溯，回溯必须显式 re-evaluate）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `durationSec` | int \| null | 是 | 签退时算出的停留秒数；作废补判时为 `null`（没有签退） |
| `distanceInM` | number \| null | 是 | 签到点到医院基准点的 Haversine 距离（米，保留 1 位小数） |
| `distanceOutM` | number \| null | 是 | 签退点距离；无签退时为 `null` |
| `flags` | array | 是 | 可为空数组；元素见下 |
| `flags[].code` | string | 是 | `DURATION_TOO_SHORT` \| `LOCATION_DEVIATION` |
| `flags[].point` | `"checkin"` \| `"checkout"` \| null | 是 | R1 为 `null`；R2 必填（逐点判定） |
| `flags[].detail` | string | 是 | 人类可读；**不得**作为判定依据被解析 |
| `flags[].distanceM` | number \| null | 否 | 仅 R2 有，便于前端显示"超了多少米" |
| `abnormal` | bool | 是 | `flags.length > 0` 的冗余，供索引与筛选 |
| `thresholds.minDurationSec` | int | 是 | 判定当时的 R1 阈值 |
| `thresholds.maxDistanceM` | number | 是 | 判定当时的 R2 阈值 |
| `ruleVersion` | string | 是 | 对应 `rule_version.version` |
| `evaluatedAt` | RFC3339 | 是 | **服务端注入**的判定时间，不用 `time.Now()` 现取 |
| `source` | string | 是 | `checkout` \| `void_backfill` \| `re_evaluate` \| `backfill_migration` |

`thresholds` 与 `ruleVersion` **同时**存，是刻意的冗余：`rule_version` 行仍可能被管理员改错，
快照里的数字才是判定当时真正用到的值。`[derived]`

### 3.4 版本号生成规则

- 版本号格式 `v<n>`，`n` 单调递增，由 `PUT /api/admin/rules` 在阈值**实际变化**时创建。
- 四个数字全部相同 → 不产生新版本，返回 `200` 与原版本（`[derived]`：避免管理员连点两次就多一个版本）。
- 新版本只影响**之后**的判定；已固化的 `visit.evaluation` 一律不动（需求说明 §6）。
- `visit.rule_version` 外键指向 `rule_version.version`，因此**不能删除任何版本行**——这是审计链的一环。

### 4.4 错误码总表

| code | HTTP | 触发条件 | 客户端该做什么 |
|---|---|---|---|
| `validation_failed` | 400 | JSON 畸形、字段缺失/未知、坐标越界、原因为空、`plannedAt` 在过去 | 高亮表单字段，不清空用户输入 |
| `not_found` | 404 | 拜访或引用的主数据不存在 | 列表刷新 |
| `forbidden` | 403 | actor 不是该拜访的代表；非管理员访问 `/api/admin/*` | 提示无权限；界面本不该出现该入口 |
| `invalid_state` | 409 | 状态机拒绝；删除窗口外；重复签到/签退/补记录 | **重新拉取该拜访**再决定下一步 |
| `conflict` | 409 | 乐观锁失败；同一代表已有进行中的拜访 | 提示后刷新；不要自动重试 |
| `internal_error` | 500 | 兜底 | 显示请求 ID，别重放 |

`invalid_state` 与 `conflict` **必须分开**：前者是"你理解的状态不对"（刷新这条记录），
后者是"别人刚改过"（刷新整页）。`[derived]` v1 已如此实现，保留。

## §5 判定函数与分层边界

### 5.1 规则函数签名

```go
// 纯函数：不碰 DB、不取时钟、不读环境变量。
// 所有"现在几点"都由调用方注入（in.EvaluatedAt），否则同一份输入会因调用时刻不同而产出不同结果。
type EvaluationInput struct {
    CheckinAt    time.Time
    CheckoutAt   time.Time      // 作废补判时为零值
    Checkin      Coordinates
    Checkout     Coordinates    // 作废补判时为零值
    HospitalBase Coordinates
    Thresholds   Thresholds     // {MinDurationSeconds int; MaxDistanceMeters float64}
    RuleVersion  string
    EvaluatedAt  time.Time      // 注入
    Source       string         // "checkout" | "void_backfill"
}

type Evaluation struct {
    DurationSec  *int64    // 无签退 → nil
    DistanceInM  *float64
    DistanceOutM *float64
    Flags        []Flag    // 全量，不短路
    Abnormal     bool
    Thresholds   Thresholds
    RuleVersion  string
    EvaluatedAt  time.Time
    Source       string
}

func Evaluate(in EvaluationInput) (Evaluation, error)
```

三条行为约定：

1. **不短路**：R1 与 R2 各自独立求值，全部命中项都返回（需求说明 §4「逐点判定，各生成一条」）。
2. **边界严格**：`duration < 300s` 异常（300 合规）、`distance > 500m` 异常（500 合规）。
   距离比较带 `1e-6` 容差仅用于吸收浮点噪声，不是测量余量（v1 `exceedsLimit` 已如此）。
3. **缺证据时不猜**：`CheckoutAt` 为零值 → `DurationSec=nil`、`DistanceOutM=nil`、不产出 R1，
   只按签到点跑 R2（需求说明 §3.2 迁移 6 的"补判"）。

### 5.2 纯函数与非纯的边界

| 层 | 可以做什么 | 不可以做什么 |
|---|---|---|
| `internal/domain` | 距离、时长、阈值比较、状态迁移表、坐标校验 | 读 DB、读时钟、读配置、打日志 |
| `internal/store` | SQL、事务、乐观锁、把 `domain.Evaluation` 落成 `evaluation` + `visit_flag` 行 | 自己算判定（必须调 `domain.Evaluate`） |
| `internal/api` | 解码、注入 `now()`、actor 判定、错误码映射 | 复述业务规则（状态守卫只调 store/domain） |

这条分层是为了让验收点 3 与 4 能用**表驱动单测**证明，而不是靠集成测试碰运气。`[derived]`

### 5.3 事务边界

**签退必须是一个事务**：写 `checkout_*` + 写 `duration_seconds` + 写 `evaluation` + 插入 N 条 `visit_flag` + 改 `status`。

```sql
BEGIN;
SELECT id, status, checkin_at, checkin_lat, checkin_lng, version
  FROM visit WHERE id = $1 FOR UPDATE;          -- 拿住行，挡住并发签退
-- （Go）domain.Evaluate(...) 产出 evaluation 与 flags
UPDATE visit
   SET status = 'CHECKED_OUT',
       checkout_at = $2, checkout_lat = $3, checkout_lng = $4,
       duration_seconds = $5, evaluation = $6, rule_version = $7,
       version = version + 1, updated_at = now()
 WHERE id = $1 AND version = $8;
INSERT INTO visit_flag (visit_id, code, point, detail, rule_version) VALUES ...;
COMMIT;
```

**为什么不能拆**：部分成功会产生两种静默错误——

- 状态改了、flags 没写进去：拜访显示"已签退 · 合规"，而它其实超短且离院 1.2 公里；
- flags 写了、状态没改：拜访停在 `CHECKED_IN`，却带着一份属于"未来"的判定。

两种都不会报错，都会让验收点 4、7、10 在无人察觉的情况下失效。`[derived]`

**作废同理**：`evaluation` 补判 + `visit_flag` 插入 + 状态迁移 + `void_*` 字段写入，同一个事务。

### 5.4 超时收敛：读时判定，没有后台任务（裁决 6-3 = B）

三条读路径（列表 / 详情 / 看板）在返回之前先调用 `store.Converge(ctx, now)`，把过期状态推成终态。

```sql
-- ① 计划超时 → CANCELLED（纯 SQL 可完成）
UPDATE visit
   SET status = 'CANCELLED',
       cancel_reason = '超时未签到（NO_CHECKIN）',
       cancelled_at  = $1,
       version = version + 1, updated_at = $1
 WHERE status = 'PLANNED'
   AND planned_at < $1 - $2::interval
RETURNING id;

-- ② 签到超时 → VOIDED 需要补判 R2，交给 Go：先占行，再计算，再写
SELECT id, checkin_at, checkin_lat, checkin_lng,
       hospital_name, base_lat, base_lng        -- 读 visit 上的快照，不 join 主数据
  FROM visit
 WHERE status = 'CHECKED_IN'
   AND checkin_at < $1 - $2::interval
   FOR UPDATE SKIP LOCKED;
-- （Go）domain.Evaluate(...) → UPDATE visit ... + INSERT visit_flag ...
```

四条约束：

1. **幂等**：条件写进 `WHERE`（状态 + 时间），重复执行命中 0 行。
2. **并发安全**：`SKIP LOCKED` 让两个并发 GET 各自处理不同行，不会对同一条重复写 `VOIDED`。
   两个事务抢同一行时，后到者看到的已是终态，`WHERE status='CHECKED_IN'` 不再命中。
3. **独立事务，先提交再读**：收敛不放进读事务里，避免"长查询占着行锁"。
4. **失败即 500**：宁愿这次读失败，也不返回一份自己知道已经过期的数据——否则"读时收敛"就退化成
   "读时假装收敛"，而验收点 10 的看板数字正是靠它才对得上。

**选 B 的代价，写在这里**：GET 不再是纯读；一次列表可能触发 N 条更新的写放大器；
每条读请求都要算一次 24h 边界，读延迟随过期记录数上升。若日后发现读放大不可接受，
改回 A（后台任务）只需要删掉 `Converge` 的调用点，`WHERE` 条件原样搬进任务即可——这是刻意让两条路共用同一段 SQL。
