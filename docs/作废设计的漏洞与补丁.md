# 自助作废（无审批）设计的漏洞与补丁

> **前提已更新（以 `需求说明.md` 为准）**：作废是自助的、无需主管审核，但**只能从 `CHECKED_IN` 出**；
> `PLANNED` 的两个出口是「取消」和「删除」，没有「作废」。计划超时 24h 归 `CANCELLED`（NO_CHECKIN），
> 不是作废。签退后作废窗口关闭。
>
> 原始分析写于状态机收敛之前，其中 P0-2「签退后还能作废」与附二的删除窗口口径已被最终状态机取代，
> 保留原文仅作推理过程的留痕。
>
> **2026-10-29 补充**：「区域主管」角色已整层移除（`需求说明.md` §1）。文中"主管看板""主管确认"等表述
> 一律按「管理员」理解——管理员只能看，不能改判定。

结论先说：**可行，但现在的版本会让"合规率"变成一个代表自己决定的分母。**

---

## 0. 核心矛盾：作废与判定抢跑

判定的输入是签到时间与坐标，判定的时机是签退。
只要"作废"能发生在"签退"之前，代表就能在**知道大概会被判异常**的时候先作废，让那条数据根本不存在。

> 系统测到的就不再是"合规率"，而是"代表愿意承担的比例"。

这条推翻了其余所有漏洞，其余都是它的变体或放大器。

---

## P0（会直接破坏系统结论）

### P0-1　作废即消失 → 异常率失真（void-to-escape）
- **场景**：代表在 2 公里外签到、停 2 分钟，估计要命中 R1+R2，直接作废。异常率、覆盖率、拜访次数全部干净。
- **后果**：异常率长期趋近 0 不是合规改善，而是数据被筛过。作废率是唯一的对冲指标，但它只能说明"废了多少"，说不出"废掉了什么"。
- **补丁（关键）**：**作废不影响判定的存在，只影响计数。**
  作废时用已有的签到时间与坐标照样跑一遍规则，把 `flags` 存进作废记录。
  看板把作废拜访单列一栏"作废中的异常"，主管点得进去。这样作废只能让它"不计入覆盖"，不能让异常"没发生过"。

### P0-2　签退之后还能作废 → 看到结果再抹掉　✅ 已由状态机堵死
- **场景**：签退 → 界面显示"异常 · 命中 2 项" → 反手作废。
- **后果**：判定形同虚设，这是比 P0-1 更直接的作弊路径。
- **补丁**：**作废窗口在签退时关闭**。签退后只允许"撤回签退"（回到 CHECKED_IN，且视为一次异常操作留痕），不允许作废。
  如果 checkout 直接进 REPORTED（跳过待补记录），那更要保证这条边不存在。

### P0-3　PLANNED 超时作废 ≠ 拜访作废
- **问题**：计划没执行（人没去）和拜访作废（去了但不算）是两件完全不同的事，混进同一个 `VOIDED` 后，
  **计划执行率**（计划 100 条、执行 70 条、未执行 30 条）就算不出来了。
- **后果**：主管最想要的"该去的去没去"这个指标消失，只剩一个说不清含义的作废率。
- **补丁**：状态可以仍叫 `VOIDED`，但必须用 `cause` 分开：`NO_CHECKIN`（计划超时未签到）/ `NO_CHECKOUT`（超时未签退）/ `MANUAL`（人工）。
  看板分两栏：**未执行** vs **已发生但作废**。

### P0-4　软删除让"计划总数"不可信
- **问题**：代表把没去的计划删掉，计划总数变小，执行率反而变好看。
- **补丁**：删除只影响"列表可见性"，不影响台账；或者干脆**不允许删除已过期的计划**（只能取消/作废）。
  计划执行率的分母必须是"曾经存在过的计划数"。

## P1（可审计性与责任）

### P1-1　超时作废是"甩锅路径"
- **问题**：不作废、直接走人，让系统 24h 后自动作废，责任就从代表变成了"系统"。
- **补丁**：超时作废必须记录**责任人 = 该拜访的代表**、超时时长、最后一次已知坐标，并与自助作废计入同一个作废率。
  系统作废只是"没人点按钮"，不是"没人负责"。

### P1-2　自助作废的留痕太浅
- **问题**：一段自由文本，"医生停诊"四个字可以解释任何事。
- **补丁**：结构化原因（医生停诊 / 走错院区 / 误签到 / 时间冲突 / 其他）+ 强制附带签到点距离，
  并按月抽样复核（例如 10%），复核发现造假按违规处理——用**事后抽样**替代**事前审批**，摩擦小、威慑在。

### P1-3　作废后立刻重建 → 洗记录
- **场景**：作废一条 2 公里外的签到，立刻新建同医生同产品的拜访，重新签到（这次坐标正常）。月底看：1 次干净拜访。
- **补丁**：同代表 + 同医生 + 同产品 24h 内重复出现，标记"重试"，看板单独计数；
  重试率 + 作废率一起看，才看得出"洗"的痕迹。

## P2（边界与工程）

| # | 漏洞 | 补丁 |
|---|---|---|
| P2-1 | 扫描与签到/签退并发（恰好在超时那一秒签到） | 服务端单事务 + 乐观锁；以签到成功为准；超时判定用"计划时间 + 宽限"，不用"任意时刻" |
| P2-2 | 手动输入坐标 + 自助作废 → 合规层沦为自觉申报 | 坐标标来源（GPS / 手填），手填降低可信度权重；关键拜访要求现场码/照片 |
| P2-3 | 作废会改写历史月份的数字（KPI 都发了还在动） | 月度封账后不可自助作废，只能走管理员"调整分录"，不覆盖原值 |
| P2-4 | 误作废不可撤销 | N 分钟内可撤回，生成 `REVOKE` 记录，而不是删掉作废记录 |
| P2-5 | 作废率本身被当 KPI 反向操纵（不敢作废 → 大量悬挂 → 集中超时） | 同时看"及时签退率"与"悬挂率"，三个数互相牵制 |

## 最小改动集（保留"不审批"，只堵住结论层）

1. **作废时照样跑规则**，`flags` 写进作废记录（P0-1）。
2. **签退后禁止作废**，只允许撤回签退（P0-2）。
3. `cause` 区分 `NO_CHECKIN / NO_CHECKOUT / MANUAL`，看板拆开统计（P0-3）。
4. 删除不影响计划台账（P0-4）。
5. 超时作废记录责任人（P1-1）。
6. 结构化原因 + 月度抽样（P1-2）。

这六条不增加任何审批动作，但把"作废"从**删除证据**变成**放弃计数**——性质完全不同。

## 一个反直觉的建议

如果一定要在"事前审批"和"事后抽样"之间选，选抽样。
事前审批的成本落在每一次正常作废上（医生停诊是高频事件），而事后抽样的成本只落在 10% 的可疑样本上，
并且它惩罚的是"造假"，不是"运气不好"。

## 附：作废 / 取消 / 删除，三者怎么分

一句话：**删除 = 本来不该存在；取消 = 主动放弃；作废 = 发生了但不算。**

三者的分界线不是"严重程度"，而是**计划时间**——事前可以改/删/取消，事后只能作废。

```
创建 ──► 计划窗口（now < 计划时间 + 宽限）──► 执行窗口 ──► 结束
         可改 / 可删 / 可取消                  可签到 / 可作废        可补记录
                                                计划时间+24h 未签到 ──► 作废(NO_CHECKIN)
```

| | 删除 | 取消 | 作废 |
|---|---|---|---|
| 回答的问题 | 这条记录本来就不该存在 | 这次不去了（主动） | 去了/到期了，但这次不算 |
| 允许窗口 | 计划时间之前 | 计划时间之前（含宽限） | 过了宽限未签到，或已签到 |
| 典型场景 | 选错医生、重复录入、测试数据 | 医生停诊、行程冲突 | 误签到、走错院区、签到后作废 |
| 数据后果 | 软删除，默认不可见 | 状态 `CANCELLED` | 状态 `VOIDED` + `cause` |
| 统计后果 | **不进任何分母**（视为从未存在） | 进"未执行"分母 | 进台账，单独计作废率 |
| 默认可见性 | 隐藏（管理员可查） | 可见（MR 可筛） | 可见（MR 可筛，主管看板有列） |
| 判定 | 不跑（无签到痕迹） | 不跑 | **要跑**（有签到坐标就必须留 flags） |

### 为什么删除必须留一个窄窗口

删除是唯一能让数字"变小"的操作：代表删掉没去的计划，执行率的分母就跟着变小。
所以删除只允许发生在**计划时间之前**——那时还没有"该去没去"这个事实，删除只是修正录入错误。
一旦过了计划时间，这条计划就必须留在台账里，只能取消或作废。

### 交互上的关键：不要让人三选一

同一时刻只暴露一个合法动作，由状态决定：

| 状态 | 界面只给这些按钮 |
|---|---|
| `PLANNED`（未到期） | 修改 / 删除 / 取消 |
| `PLANNED`（已过宽限） | 作废（系统已自动作废，无需手动） |
| `CHECKED_IN` | 签退 / 作废 |
| `CHECKED_OUT` | 提交记录（**作废窗口已关闭**） |
| 终态 | 只读 |

三个按钮从来不会同时出现，用户不需要理解三者的边界，系统替他决定。

### 技术上它们是一样的

三者都是**软标记**（append-only，物理行永不删除），区别只在两处：
1. 是否进分母（`deleted` 不进；`CANCELLED` / `VOIDED` 进）；
2. 是否要跑判定（有签到痕迹就必须跑）。

所以"作废 vs 删除"不是权限问题，而是**语义与统计口径**问题——这也是为什么它必须在需求阶段定死，不能留给实现者随手决定。

## 附二：宽限期、状态与提示（要不要加一个"已到期"状态）

### 先修锚点：删除看 createdAt，取消看 plannedAt

> ⚠️ **与最终口径的差异**：本节主张删除只看 `createdAt + 1h`；`需求说明.md` §3.2 迁移 5 采用的是
> **两个条件同时成立**（`now < plannedAt − 1h` 且 `now − createdAt ≤ 1h`）。实现按 `需求说明.md`，
> 本节保留为备选方案。

"计划时间之前才能删"这条规则，对**临近的计划**是失效的：10:00 创建一条 10:05 的计划，10:06 就再也不能删了。
根因是把两个不同的窗口绑在了同一个时间锚点上：

| 窗口 | 回答的问题 | 正确的锚点 |
|---|---|---|
| 删除窗口 | "我刚刚录错了，能撤回吗" | **createdAt + 1h**（与计划时间无关） |
| 取消窗口 | "这次我不去了，能撤单吗" | **plannedAt + 1h** |

换成 createdAt 后，5 分钟的计划照样有整整一小时的纠错窗口，问题消失。

### 要不要加"已到期未签到"状态？

**不要。** 理由三条：

1. **它是时间的函数，不是事件。** `now > plannedAt + 1h` 每时每刻都在变，没有"谁做了什么"。把它塞进状态机，
   状态就会随时间自己变，而状态机的价值恰恰是"只记录发生过的事"。
2. **它会过期。** 状态必须由调度器写入；调度器停摆，库里的状态就和现实不一致，而权限判断又会读到这个陈旧状态。
3. **权限不是状态。** 加状态的实质是想用 `status` 控制按钮显隐——但按钮该不该显示，是谓词的结果，不是事实。

### 正确的三层拆分

| 层 | 内容 | 载体 |
|---|---|---|
| **事实** | 谁在什么时候做了什么（签到、签退、作废） | `status` 状态机 |
| **判定** | 现在能不能删 / 取消 / 签到 / 作废 | 纯函数 `canX(visit, now, policy)` |
| **账目** | 这条算不算数、算在哪个口径 | 报表聚合，或物化的 `lapsed_at` 时间戳列 |

"到期"属于第三层：需要索引和报表时，加一列 `lapsed_at`（时间戳），**加列不加态**。

### 关键：读路径也要判定，状态只是缓存

自动作废（`NO_CHECKIN`）仍然需要调度器落库，因为报表要查。但权限判断**不能依赖它是否已经落库**：

```
canCancel(v, now) = v.status === 'PLANNED' && now <= plannedAt + CANCEL_GRACE
```

即使调度器今天没跑，超过宽限的计划也取消不了——因为它算不出来。
状态是物化的缓存，谓词才是真相。调度器迟到只影响报表，不影响防作弊。

### 删除的时点决定它入不入账

允许删除，不等于允许抹掉记录。用**删除发生的时点**决定它算不算数：

| 删除时点 | 是否计入"未执行" |
|---|---|
| 计划时间之前 | 否（它从没成为过承诺，属于录入纠错） |
| 计划时间之后 | **是**（它已经是一条承诺，删掉也要入账） |

这样"允许纠错"和"不许洗数"就不冲突了——你能删掉碍眼的行，但洗不掉那一笔账。

### 提示该放在哪三处

1. **创建时**：`plannedAt - now < 1h` 时提示"该计划 5 分钟后到期，请先核对医生与药品"。
2. **列表里**：显示"距计划时间 5 分钟 / 已过 25 分钟"，让人对窗口有感知。
3. **按钮处**：删除按钮不用消失，而是禁用 + 说明——"已进入执行窗口，只能取消或签到"。
   消失会让人以为系统坏了，禁用并解释才会让人改变行为。

## 附三：MR 自助取消版状态机（v3）

图：`demo/assets/state-machine-v2.svg`

**7 个状态 · 8 条迁移**，完成 / 取消 / 作废 三套独立统计。

| # | 迁移 | 触发 | 守卫 | 统计归属 |
|---|---|---|---|---|
| 1 | `PLANNED → CHECKED_IN` | MR 签到 | 坐标必填 | — |
| 2 | `CHECKED_IN → CHECKED_OUT` | MR 签退 | 判 R1/R2，固化判定 | **完成** |
| 3 | `CHECKED_OUT → REPORTED` | MR 提交记录 | 谈话要点必填 | **完成**（记录完整） |
| 4 | `PLANNED → CANCELLED` | MR 取消 | 需原因 | **取消** |
| 5 | `PLANNED → CANCELLED` | 系统超时（NO_CHECKIN） | 计划时间 + 24h 未签到 | **取消** |
| 6 | `PLANNED → DELETED` | MR 删除 | 免原因，仅纠错窗口内 | 不入账 |
| 7 | `CHECKED_IN → VOIDED` | MR 手动作废 | 需原因 | **作废** |
| 8 | `CHECKED_IN → VOIDED` | 系统超时（24h 未签退） | 原因记"超时" | **作废** |

### 一处口径修正：过期未签到属于「取消」，不是「作废」

作废的语义是"人到了但这次不算"（有签到证据）；取消的语义是"没去成"。
把 NO_CHECKIN 归进作废，会让作废率混进根本没到过医院的人，这个指标就失去含义了。
所以：**作废只从 `CHECKED_IN` 出**，`PLANNED` 的两种结局是「取消」和「删除」。

### 这套模型已经自动堵上的一个洞

作废只在签退之前可用，签退后立即进入"完成"且判定已固化——**"看到异常再作废"这条路不存在了**。
这是 v3 相比审批版的实质进步。

### 还必须补的三件事

1. **手动作废要补跑 R1/R2**。作废发生在判定之前，不补跑就仍可在"估计要判异常"时作废，
   签到证据随记录一起变成"不算数"。做法：作废时用签到时间与坐标跑一遍规则，`flags` 存进作废记录，
   看板单列"作废中的异常"。
2. **删除免原因可以，但要留 who/when**。原因字段可以没人填，操作人和时间必须系统自动记，
   否则"谁在什么时候删了 30 条计划"查不出来。
3. **`CHECKED_OUT` 计入完成之后，`REPORTED` 的含义变了**：它不再是"完成"，而是"记录完整"。
   于是需要两个指标——完成率（签退）与记录完整率（补记录），且"签退后一直不补记录"要有出口
   （`NO_REPORT` 超时或进主管待办）。

### 待确认：删除窗口的第二个条件

"创建时间 + 开始前 1 小时"里，"创建时间"具体指什么？

```
canDelete = status === 'PLANNED'
         && now < plannedAt - 1h        // 距离开始还有 1 小时以上
         && now - createdAt <= W        // W 待定：创建后多久内允许纠错
```

- `W = 1h`：只能纠正"刚建错"的计划，最严格；
- `W = ∞`：只要离开始还有 1 小时就能删——那就等于"1 小时前的计划随时可删"，
  容易出现"提前几天建的计划，临近前想删就删不了（已进入 1 小时）"，但更早随时能删。
