# 部署验证记录

> 目标：证明 `docker compose up --build` 能把这套东西跑起来。
> **结论：已在本地完整验证通过**——镜像构建、两个容器、健康检查、自动迁移与播种、
> 十条验收全过。下面是证据、方法，以及为此在本机搭运行时踩的坑。

## 环境

| 项 | 值 |
|---|---|
| 系统 | macOS 27.0.1（arm64） |
| 容器运行时 | 原本一个都没有（无 Docker Desktop / podman / colima / Homebrew）。现在用 **colima + Apple Virtualization.framework** 在用户态装了一套，不需要管理员权限 |
| Go | 1.27.2（`go.mod` 声明的最低版本是 1.25.0） |
| 数据库 | 本机 Postgres 16.15，端口 55432（Postgres.app） |

## 已验证（附证据）

### 1. compose 文件本身

用 Ruby 的 YAML 解析器读进来做结构断言，不是"看起来对"：

```
services: db, app
app 环境: PORT, POSTGRES_DSN, TZ
db 端口映射: 55432:5432
volumes: postgres-data
```

断言通过：两个服务都在、`app` 有 `POSTGRES_DSN` 与 `healthcheck`、`db` 有 `healthcheck`、
`depends_on` 的 condition 是 `service_healthy`、端口 `8080:8080`。

### 2. 构建上下文

`.dockerignore` 之前漏了 `.tools-run/`（本地二进制与日志），上下文是 **16.1 MB**。
补上之后：

```
加白名单后上下文: 68 个文件 · 0.5 MB
```

这不只是速度问题：`COPY . .` 会把 16 MB 的 Darwin 二进制一起塞进 builder stage。

### 3. Dockerfile 静态审查

| 检查 | 结果 |
|---|---|
| 多阶段（node → golang → alpine） | ✅ |
| 前端在独立 stage，不进运行镜像 | ✅ |
| `go.mod/go.sum` 先拷（缓存层） | ✅ |
| 用 web stage 的产物，不重复构建 | ✅ |
| `CGO_ENABLED=0`（alpine 是 musl，必须有） | ✅ |
| `USER 10001:10001`（数字 uid，便于 `runAsNonRoot` 校验） | ✅ |
| 装了 `tzdata`（按月分桶依赖 `Asia/Shanghai`） | ✅ |
| `EXPOSE 8080` 与 compose 的映射一致 | ✅ |

### 4. 用 Dockerfile 的同一条命令交叉编译到目标平台

```bash
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o /tmp/server-linux ./cmd/server
```

```
ELF 64-bit LSB executable, ARM aarch64, ... statically linked, stripped
```

`statically linked` 是 alpine 能跑它的前提——动态链接的 glibc 二进制在 musl 上会直接报
`not found`，而这条错误经常被误读成"文件丢了"。

### 5. 按 compose 的形状起一个库，跑同一个二进制

建了与 compose 同形的角色与库（`/visits`，非默认端口），DSN 结构与 compose 里那条一致，
`TZ=Asia/Shanghai`：

| 期望 | 实际 |
|---|---|
| 首次启动自动迁移 | 10 条迁移依次应用 |
| 自动播种 | 10 条拜访 |
| `/healthz`（compose 的 healthcheck 打的就是它） | `{"service":"field-visit-compliance","status":"ok"}` |
| 首页可访问 | 200 |
| 月分桶用 `Asia/Shanghai` | `months: 2026-06 … 2026-11`，`totalVisits: 8` |

### 6. `restart: unless-stopped` 依赖的幂等性

第二次启动：**应用 0 条迁移**，数据仍是 10 条。迁移器用 `schema_migrations` + advisory lock，
所以容器重启、甚至两个副本同时起，都不会重复迁移。

### 7. 运行期不写盘

容器里是 `USER 10001` 加只读根文件系统。进程跑起来后，除日志到 stdout 之外**没有创建任何文件**
（工作区前后对比无新增）。所以不需要可写挂载。

## 容器验证（2026-11-01，本机实跑）

### 跑起来的过程

```bash
docker compose up --build -d
```

```
Container submission-db-1  Healthy
Container submission-app-1 Starting → Started
```

| 检查 | 结果 |
|---|---|
| `docker compose ps` | 两个服务都 `(healthy)` |
| `curl localhost:8080/healthz` | `{"service":"field-visit-compliance","status":"ok"}` |
| 首页 | `200`，中文界面完整渲染 |
| 种子数据 | 10 条拜访，七种状态都在 |
| `docker compose exec app id` | `uid=10001(app)` —— 非 root 生效 |
| 镜像基础 | `Alpine Linux`（musl，静态二进制跑得起来） |
| `TZ` | `Asia/Shanghai`，`/usr/share/zoneinfo/Asia/Shanghai` 存在（月分桶依赖它） |
| 镜像体积 | `submission-app:latest` **30.8 MB** |

### 冷启动

`docker compose down -v` 删掉卷再 `up -d`：两个服务 12–15 秒内 healthy，**迁移表 10 条、
拜访 10 条**——首次启动的自动迁移与播种是通的，不是只有第二次能用。

### 重启

`docker compose restart app` → 8 秒后 healthy，首页 200。迁移器靠 `schema_migrations` +
advisory lock，重复启动不会重复迁移（`restart: unless-stopped` 依赖这一点）。

### 验收脚本打到容器上

```bash
BASE=http://localhost:8080 PGPORT=55432 PGUSER=veeva PGPASSWORD=veeva PGDATABASE=visits \
  scripts/acceptance.sh
```

```
通过 13 · 失败 0
```

十条验收全部在**容器里跑的服务**上通过，与之前在本机进程上跑的结果一致。

### 为跑起来在本机装了什么

没有 Docker Desktop、没有 Homebrew、没有管理员权限，所以全部落在工作区里（`.tools/docker/`）：

| 组件 | 版本 | 说明 |
|---|---|---|
| colima | v0.10.3 | 用户态的 Docker 运行时，`--vm-type vz` 用 Apple 的虚拟化框架，不需要 qemu |
| lima | 2.2.1 | colima 底下的 VM 管理 |
| docker CLI | 29.9.2 | 官方静态二进制 |
| docker compose | v5.6.1 | 作为 CLI 插件放在 `DOCKER_CONFIG/cli-plugins/` |

两个坑值得记：

1. **`colima` 要写 `~/Library/Caches/colima`**，被沙箱拒绝。解法不是提权，而是把 `HOME`
   指到工作区（`HOME=.tools/home`），缓存目录就跟着进去了。
2. **第一次启动卡在 `Explicitly start ssh ControlMaster`**，每次 ssh 间隔正好两分钟——
   guest 里 DNS 解析超时。删掉 VM、加 `--dns 1.1.1.1 --dns 8.8.8.8` 重建后一次通过。

## 仍然没验证的

只剩这些，都是"换一台机器才知道"的类别：

| 项 | 为什么没验 |
|---|---|
| x86_64 主机 | 本机是 arm64；compose 里没有平台限定，镜像会按主机架构构建 |
| 别的 Docker 版本（如 20.10） | 本机是 29.5.2 / compose v5.6.1 |
| 公网拉取速度 | 镜像已在本地，未测冷拉取耗时 |

## 复跑

```bash
# 运行时（本机已有；换机器需按上面那节装一遍）
colima start --vm-type vz --cpu 2 --memory 3 --disk 20

cd submission
docker compose up --build -d
docker compose ps                     # 两个服务都应是 (healthy)
curl -s localhost:8080/healthz
open http://localhost:8080            # 中文界面 + 种子数据

# 十条验收打到容器上
BASE=http://localhost:8080 PGPORT=55432 PGUSER=veeva PGPASSWORD=veeva PGDATABASE=visits \
  scripts/acceptance.sh

docker compose down -v                # 收工，连卷一起删
```
